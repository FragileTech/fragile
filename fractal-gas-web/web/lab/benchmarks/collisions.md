# Flight collision optimization

Measured on 2026-09-08 using release WASM in Node, without rendering. These are
observations on a shared host, not latency guarantees. CPU contention caused
substantial variation in individual samples; retain the raw samples when
repeating the comparison.

The stock harvesting scene used seeds 7, 11, and 19, with 1 and 8 threads. Wave
Jump retained 128 walkers, horizon 64, 12 action frames, noise 0.2, inherited
action perturbations, no elites, and recording mode 1. No planner defaults,
gravity, masses, or materials were changed.

| Workload | Threads | Before (ms) | After (ms) | Speedup |
|---|---:|---:|---:|---:|
| Regular fixed rollouts | 1 | 34.37 | 7.94 | 4.33× |
| Flight fixed rollouts | 1 | 718.75 | 388.71 | 1.85× |
| Regular fixed rollouts | 8 | 19.83 | 3.11 | 6.37× |
| Flight fixed rollouts | 8 | 263.26 | 102.14 | 2.58× |
| Regular planner search | 1 | 941.68 | 615.80 | 1.53× |
| Flight planner search | 1 | 10066.33 | 4754.41 | 2.12× |
| Regular planner search | 8 | 748.01 | 289.76 | 2.58× |
| Flight planner search | 8 | 5302.90 | 1996.79 | 2.66× |

Fixed rollouts restore the same baseline snapshots for both engines, then run
32 worlds for 120 frames each. Episode termination is disabled in that fixture,
so every sample executes 3,840 world frames. Each seed has one warm-up and three
timed repeats; the table reports the median of the per-seed medians. The shared
starting snapshots were generated by 180 neutral-action frames in the original
engine. The baseline rollout reports 124,768 contacts and the updated rollout
95,392: the new solver counts continuing wall contacts once per substep, and
trajectories also change.

Planner measurements warm the full-size controller once, then time a search
for each seed. The table reports the median over those seeds. Trajectories are
not identical: in flight, updated seed 11 reaches an all-dead fallback after 28
search steps rather than 64. The fixed-work comparison is therefore the primary
physics performance check. The other two updated flight seeds search all 64
steps. The 2× stepping target was met with the default eight threads; the
single-thread fixed workload improved by 1.85×, below that target.

Raw WASM samples are in [collisions.json](collisions.json). Diagnostic native
counts are in [one-thread](collision-counters-1.csv) and
[eight-thread](collision-counters-8.csv) CSVs. Those instrumented runs overlapped
other checks, so their timings are not used in the speedup table.

## Changes and compatibility

The engine adds a swept-circle/segment filter after its existing grid and AABB
checks, caches static wall geometry and normalized axes, and reuses dynamic
geometry at unchanged poses. It also caches regions proven to contain no walls.
Continuous collision advancement uses a conservative bound on motion toward the
current separating axis, avoiding work caused only by tangential motion. Circle
rotation does not enlarge the collision-motion bound.

Low-speed wall contacts share normal and tangential impulses within a substep.
Restitution is applied once per new impact and friction is limited by the
accumulated normal impulse. Rotating polygons retain the separation offset needed
to advance past a contact without repeatedly exhausting the impact limit.
Uncertain sweeps retain continuous collision detection and its iteration limits.

Caches and contact impulses do not enter snapshots or scene exports. Per-world
cache validity is reset, and changed poses rebuild geometry. Cloning, batching,
thread assignment, and restored futures remain deterministic under the updated
engine. Existing recordings remain viewable; re-simulating earlier action
sequences can produce different trajectories and collision counts.

## Reproduction

Before rebuilding, copy the four `control*.mjs`/`control*.wasm` engine files into a
separate baseline directory. Run the baseline first to create shared fixed-work
snapshots, then use that same `--roots` directory for the updated engine:

```sh
node tools/control-collision-benchmark.mjs --engine-dir /tmp/control-baseline \
  --roots /tmp/control-collision-roots --output /tmp/before.json
node tools/control-collision-benchmark.mjs \
  --roots /tmp/control-collision-roots --output /tmp/after.json
```

Commands run from `fractal-gas-web`. Optional `--fixed-only`, `--threads 1,8`,
and `--seeds 7,11,19` select workloads without changing their planner budget.
Do not rebuild the engine or run other heavy checks during a timed comparison.

Detailed collision counters are available only in diagnostic native builds:

```sh
cmake -S . -B /tmp/control-counts -DFG_CONTROL_ONLY=ON \
  -DFG_CONTROL_PROFILE=ON -DCMAKE_BUILD_TYPE=Release
cmake --build /tmp/control-counts --target fg_control_collision_benchmark
/tmp/control-counts/control/fg_control_collision_benchmark scene.json 8
```

Use a flight scene with `physics.lethal_walls` disabled for a sustained fixed
workload. Output includes advanced frames, contacts, grid queries, candidate
edges, separation checks, and continuous-collision iterations. Instrumentation
is compiled out of normal native and WASM builds; native trajectories may differ
from WASM and their timings should not be compared directly.
